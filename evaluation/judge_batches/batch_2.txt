15. Required fact: A proxy re-serialized the JSON body, which changed the raw bytes and broke Stripe signature verification.
   Model answer: Here’s what the repo says.

**Why it failed:** Stripe signs the **exact raw HTTP body bytes**. In staging, a proxy on a new path was reading the body as JSON and **forwarding a re-serialized** body. That changes the byte stream even when the JSON is **semantically the same** (different spacing, key order, formatting, etc.), so HMAC verification against `stripe-signature` fails.

**What fixed it:** Stop transforming that path—**bypass the proxy’s parse/re-serialize for** `/api/webhooks/stripe`—and keep receiving the body as raw JSON (as in `docs/incidents/2026-03-05-stripe-signature-staging-incident.md` and `docs/integration/webhooks.md`).

So the failure was **transport-level fidelity**, not “wrong” JSON meaning: signature verification is over bytes, not over parsed object equality.
