## Artifact chain (proxy vs Stripe webhooks)

1. **`stripe-signature` is checked against the request body**  
   The integration doc says the value is a timestamp + HMAC and is **verified against** `STRIPE_WEBHOOK_SECRET` (i.e. verification uses the body bytes the server sees, not “JSON equality” in memory).

2. **Stripe signs the original raw bytes**  
   The incident **Root Cause** section states: *“Stripe signs the original raw bytes. The proxy changed the payload, so the service could no longer validate the `stripe-signature` header.”*

3. **Why “same JSON” still breaks things**  
   The **webhooks** integration doc requires the endpoint to get the **raw, unparsed request body**. It explicitly says that for a proxy (or tests) you must forward **raw bytes**, not a parsed object re-serialized—even if the JSON content is the same—because that path **will cause signature verification to fail** (with an error like *“No signatures found matching the expected signature for payload”*).

So the chain is: **Stripe signs exact raw body bytes → `stripe-signature` matches only those bytes → a proxy that parses and re-emits JSON changes the byte stream (whitespace, ordering, encoding, etc.) while fields may still “match” logically → HMAC no longer matches → webhooks fail verification.** That is the artifact chain the repo documents; it is about **byte identity**, not whether the JSON fields are the same after parsing.
